## The rule this document exists to enforce

**No pilot begins at [ORGANIZATION NAME] until Section 3 is filled in and
signed.** Most enterprise AI pilots have no written stop condition, which is
precisely why they never stop: the window lapses, the tool is still installed,
nobody decides anything, and a pilot becomes an adoption by default. The stop
condition below is a required field, not a suggestion, and the approver signs it
before the first day rather than after the last.

Large organizations pilot. They do not roll out. One site, one owner, one
window.

A pilot runs at **one** site. If two sites want it, the second waits for the
closing decision in Section 5.

## 2. Success criteria, declared in advance

Write these before the start date. Criteria written afterwards are a description
of what happened, not a test.

| What we expect | The number that counts as success | How it will be measured | Measured by |
| --- | --- | --- | --- |
| Time returned to staff |  |  |  |
| Quality of the work product |  |  |  |
| Staff would keep it (share saying yes) |  |  |  |
| [OTHER CRITERION] |  |  |  |

At least one criterion must be about the children or the families, not only
about staff time. For Tier 3 pilots, one criterion must be whether performance
holds for children who are dual language learners and children with
disabilities, because §1302.102(c)(2) already requires disaggregated analysis
and a pilot is the cheapest place to find out.

## 3. Stop condition — required

**This pilot stops immediately, without a meeting, if any of the following
happens.** These are not warnings. Each one ends the pilot on the day it occurs.

- Child or family information reaches a place the written agreement does not
  cover.
- The tool produces an output that would affect a specific child — a flag, a
  score, a referral suggestion — that was not part of the approved scope.
- The vendor changes terms, switches on a feature we did not approve, or cannot
  answer a question in the Vendor Question Sheet within [TEN BUSINESS DAYS].
- Any use listed in the charter's standing prohibitions occurs, or the tool
  turns out to be capable of one.
- A family objects and the objection cannot be honored while the pilot runs.
- [LOCALLY DEFINED STOP CONDITION — WRITE ONE]

**And the ordinary ending:** if the success criteria in Section 2 are not met by
the end date, the pilot ends on the end date. The tool is uninstalled, access is
revoked, and the Register row is closed. Nothing continues by default.

Who may stop it: the pilot owner, the site director, the [AI GOVERNANCE LEAD],
or any AI Review Group member, acting alone. Stopping requires no approval.

Signed by the pilot owner:

## 4. Notice to staff and families

Both notices go out before the first day. Neither is a consent form.

**To staff at the pilot site:** "From [START DATE] to [END DATE] we are trying
out [TOOL CATEGORY — e.g. A SCHEDULING TOOL] at this site only. [OWNER NAME] is
running it and is who you ask. You will not be evaluated on how much you use it.
If it does something strange, call [ESCALATION ROLE] at [PHONE] — that call is
never held against you. We have written down in advance what would make us keep
it and what would make us stop, and we will tell you which one happened."

**To families at the pilot site:** "Between [START DATE] and [END DATE], our
[SITE NAME] is trying out a computer tool that helps staff with [PLAIN
DESCRIPTION OF THE WORK]. [SAY WHETHER IT TOUCHES INFORMATION ABOUT YOUR CHILD,
AND WHAT KIND]. No computer tool decides anything about your child here. A
person decides. You can ask us anything about this, and you can ask to see our
list of approved tools and our agreement with this company. Questions go to
[NAME], [ROLE], at [PHONE] or [EMAIL]."

For a Tier 3 pilot, notice is not enough. Separate parental consent is required
before any child's information enters the tool, and a family that says no keeps
the same services.

## 5. Closing decision record

Completed within [TEN BUSINESS DAYS] of the end date, filed with the
[AI GOVERNANCE LEAD], and reported to [BOARD OR OWNER] at the next quarterly
item. A pilot with no closing record is treated as stopped.

| **Decision: adopt / stop / extend once** |  |
| Reasons, in two or three sentences |  |
| If adopt: tier, approver, rollout sequence, Register row updated |  |
| If stop: uninstall date, data deletion confirmed by vendor on [DATE] |  |
| If extend once: new end date, what specifically we still need to learn |  |

**Extend once means once.** A pilot may be extended a single time, for a stated
question that the first window could not answer. There is no second extension.
If the question is still open at the second end date, the answer is stop.
